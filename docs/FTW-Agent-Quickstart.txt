FTW · WorkBuddy 和 Codex 接入说明（Windows）

适用于 FTW 1.1.7。Schema 27，当前提供 102 个 MCP 工具。

1. 使用同一份工作台

完整解压 ZIP，双击 workbench.exe。在「系统状态」查看实际数据目录。保留 workbench.exe、ftw-core.exe、ftw-mcp.exe 和 portable.flag 在同一目录。客户端中的 MCP 命令应指向同目录的 ftw-mcp.exe，例如 D:\FTW工作台\ftw-mcp.exe。移动目录后需要更新该路径；使用工作台的原目录更新时路径不变，无需重新配置连接器。

2. 本机直接连接

在同一 Windows 用户下正常启动 WorkBuddy 即可使用 FTW，无需登记 Agent、输入令牌或设置环境变量。

本机 MCP 客户端共享“本机 Agent”身份，因此操作记录和自动发信授权也按该身份执行。工作台可以暂停或恢复本机接入；自动发信仍需用户在工作台保存允许的账户、用途和限额。

3. 配置 WorkBuddy

打开 FTW 侧边栏的「使用指南」，复制当前工作台生成的 WorkBuddy 配置。在 WorkBuddy 中打开「专家·技能·连接器 → 连接器 → 自定义连接器」，进入 MCP 服务管理并粘贴。已有其他服务时，复制单独的 ftw 片段，放入 mcpServers 的花括号内并用逗号分隔，保留原有服务。已有 ftw 时请更新该条，不要重复添加。保存后按提示信任或刷新连接器。

  {
    "mcpServers": {
      "ftw": {
        "type": "stdio",
        "command": "D:\\FTW工作台\\ftw-mcp.exe",
        "args": []
      }
    }
  }

请按实际解压位置替换 command。JSON 里的 Windows 路径需要双反斜杠。无需在 JSON 里填写环境变量或令牌。

4. 配置 Codex 和其他客户端

在客户端的 MCP 设置中添加本地 stdio 服务，命令同样指向本工作台的 ftw-mcp.exe，参数留空。本地客户端统一使用“本机 Agent”身份。

5. 验证和发信

在 WorkBuddy 或 Codex 的本地任务中输入：
  请调用 FTW 的 get_workbench_context 和 list_customers，只验证连接，不发送邮件。

在 FTW「邮件中心 → 发件账户」配置并测试 SMTP，在「IMAP 收件」配置并测试 IMAP。需要 Agent 自动发信时，在「Agent 发信权限」选择“本机 Agent”、发件邮箱、用途和限额，点击「保存发送权限」；也可以选择逐封审批。发信测试使用你自己授权的测试收件地址。

6. 常见情况

• 显示已连接但业务调用返回 mail_agent_unregistered：检查 MCP 路径是否指向新版 FTW，并重启工作台和 MCP 客户端。新版不读取 FTW_AGENT_TOKEN。
• 返回 mail_agent_paused：由工作台用户恢复该 Agent 的接入。
• 客户数据不一致：核对 FTW「系统状态」的数据目录和 MCP 命令路径，确保它们属于同一份工作台。
• 发送权限不足：在 FTW 查看发送模式、Agent、发件账户、用途和限额；连接授权与发送授权分开管理。
• 发送结果未知：先核对发件记录或邮箱服务商记录，不要盲目重发。SMTP 已接受不代表一定送达。
• 需要反馈故障时，在「系统状态 → 导出诊断报告」保存 JSON。窗口无法打开时，双击便携目录的 FTW-Diagnostics.cmd。查看报告后，随出错时间、操作步骤一并反馈。
