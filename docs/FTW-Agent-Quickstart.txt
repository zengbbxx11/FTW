FTW · Codex 和 WorkBuddy 接入说明（Windows）

1. 先确认两个客户端要操作哪一份工作台

完整解压 ZIP，双击根目录的 workbench.exe。在「系统状态」查看实际数据目录。
把同一目录里 ftw-mcp.exe 的绝对路径分别填入 Codex 和 WorkBuddy。保留 workbench.exe、ftw-core.exe、ftw-mcp.exe 和 portable.flag 在同一目录。MCP 会按需启动 Core。
例如测试包解压到 D:\FTW-验收，则两边都填 D:\FTW-验收\ftw-mcp.exe。样本版根目录自带 8 位客户；acceptance\workspace 是另一个空工作区。迁移目录后要更新两个客户端的 EXE 路径。
请使用本机 Windows 桌面客户端和本地任务，同一个 Windows 账户下的两个客户端可以共用这份数据。

2. Codex 桌面

打开「设置 → MCP 服务器 → 添加服务器」，名称填 ftw，传输选 STDIO，命令填刚才复制的 ftw-mcp.exe 完整路径，参数留空。保存后按界面提示重启，再开本地会话。输入 /mcp 查看连接。

已安装 Codex CLI 时，也可在 PowerShell 执行以下命令。替换示例路径后执行一次即可。
  codex mcp add ftw -- 'D:\FTW-验收\ftw-mcp.exe'
  codex mcp list

3. WorkBuddy 桌面

进入左侧「插件 → MCP 服务器 → 配置 MCP」。选择用户级供多个项目复用，或项目级仅用于当前项目。在 mcpServers 对象中添加 ftw，保留已有服务条目。下面是一份完整空白配置示例。JSON 里的 Windows 路径需要使用双反斜杠。

  {
    "mcpServers": {
      "ftw": {
        "type": "stdio",
        "command": "D:\\FTW-验收\\ftw-mcp.exe",
        "args": []
      }
    }
  }

保存后查看 ftw 状态。显示已连接后开启新的本地任务。

4. 用一句话验证，查客户和邮件草稿可先用人工审批模式

把下句分别粘贴给 Codex 和 WorkBuddy：
  请调用 FTW MCP 的 list_customers，搜索「验收样本」，列出返回的客户姓名和阶段。本次仅查询。若工具不可用，请报告连接错误。

样本版会返回 8 位。正式工作区则用一位你已知的客户姓名核对。能读到正确数据后，打开同目录 FTW-Agent-Workflows.txt，把相应任务段落复制到对话里。工作台可在人和 Agent 之间交接处理。

5. 邮件设置和交接

• 草稿前先在 FTW「邮件中心 → 发件账户」配置 SMTP 并点「测试 SMTP」。只想验收 CRM 时可跳过。样本包里的联系人均为虚构，发信测试请用你授权的测试收件地址。
• 逐封审核：Agent 写草稿并提交审核 → 用户在 FTW「邮件中心 → 邮件草稿」核对并点「人工批准」 → 用户点「发送已批准版本」，或回到 Agent 明确要求发送这一封批准的草稿 → 查看 SMTP 结果。审批随草稿修订生效，通常 30 分钟内提交。超期或改稿后重新审核。
• 允许 Agent 自动发信时，在「邮件中心 → Agent 发信权限」分别登记 Codex 和 WorkBuddy，每个客户端用自己的令牌。首次设置时界面预选可用 Agent、发件邮箱、用途和最大限额。检查范围并点击「保存发送权限」后生效。
• 自动发信令牌只传给对应本机 MCP 进程的 FTW_AGENT_TOKEN 环境变量。Codex 可在对应的 MCP 条目设置 env_vars = ["FTW_AGENT_TOKEN"]，从已为该 Codex 进程设置的环境转发。WorkBuddy 使用该客户端提供的本地凭据注入方式向 STDIO 进程传入相同变量名。令牌值应由各客户端自己的启动环境或本地凭据功能提供。能安全注入后再用自动发信，普通接入、查客户、起草和逐封审批均可先做。避免把令牌写入 JSON/TOML 明文配置、项目文件或对话。
• 收件：在「邮件中心 → 收件设置」配置 IMAP 并点「测试 IMAP」。同步后可让 Agent 查回复，也可由用户在「待核对归属」处理归属不明的来信。

6. 常见情况

• 工具未出现或连接红灯：确认配置的是本地 STDIO、EXE 路径存在、参数为空，重启客户端后开新任务。
• 能连接但客户不对：常见原因是两个客户端连到了不同解压目录。从 FTW「系统状态」核对实际目录，再检查客户端配置。
• 发件账户为空：在同一份 FTW 配置 SMTP，再查 list_email_accounts。
• 需要人工批准或授权失败：在 FTW 查看草稿修订、发信模式、Agent 授权、发件账户和用途。权限由 FTW 执行。
• 发件结果未知：先核对发件记录或邮箱服务商记录，暂停重发。SMTP 已接受仅表示服务器接受提交；查客户回复还要查看 IMAP 同步情况。
