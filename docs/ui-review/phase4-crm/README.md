- **公司与多联系人。** 在客户详情打开公司工作区，按公司名称与地区查找在用联系人。邮件状态、客户阶段与沟通历史各自独立。关联现有客户会核对两个记录的版本及工作区数据版本，只补充空白的公司或地区。新增联系人使用同一客户编辑器和查重流程。
- **质量检查。** 从「客户管理 → 更多客户操作 → 客户数据质量」进入。全库统计、问题分类、优先级、问题详情与修复入口接通 Core。共享邮箱仍会进入查重。公司或网站相同的候选还须姓名相同。发信异常可进入原记录，缺失或异常客户属性可进入相应编辑分区。
- **视觉调整。** 第一轮截图发现返回、邮件和客户资料链接的图标会与文字分行。统一为同行对齐后复验。1280 × 720 下表格和详情仍并排，公司名称、邮箱或日期较长时允许换行。
- **实现与范围。** 新增桌面 IPC `company_contacts`、`associate_company`，扩展 `customer_quality` 的关键词和具体邮件定位。复用 Lucide、Radix 搜索弹层、FTW 表格与状态组件、TanStack Query。公司分组使用已保存的联系人属性，显示的资料来自当前联系人。SQLite Schema 维持 16。 [开源组件来源](../THIRD_PARTY.md)

## 实际回归

- 在 Windows 桌面验证同组两位联系人状态独立、禁止覆盖不同公司或地区、关联后即时刷新并留下审计，以及预填新增与重复提示。
- 在质量页验证按公司筛查异常邮箱、通过 Core 保存修复、修复后退出结果，以及打开指定的提交结果未知邮件。两处桌面视口下均检查了页面无横向溢出。高级筛选的 OR 预览与应用后表格均返回预期的 5 位客户。
- 前端 lint、TypeScript、Vite 构建、Tauri 工作区构建、30 项 Rust 测试、2 项数据刷新测试及两版 MCP stdio 回归通过。Vite 仍提示主包约 752 kB。测试使用隔离记录和模拟传输。
- 本次仅完成分阶段复验与[功能盘点](../IMPLEMENTATION_STATUS.md)。正式便携版发布、真实邮件联调、Win11 与系统高倍缩放的统一验收暂停。
