- **总览。** 显示客户、收发邮件、最近备份、近期操作和数据管理入口。客户数含归档，邮件数取收件和已提交记录。客户附件与 Agent 数据变更从原有入口访问。
- **备份。** Core 读取 SQLite 完整性和迁移指纹，核对配套资料的长度和哈希。实际恢复再次执行校验，保存当前状态为安全快照，再激活目标数据库。安全快照与激活期间使用同一个工作区数据库连接。手动备份与成功恢复均写入操作记录。
- **客户 CSV。** Core 返回已识别的表头字段与跳过原因。确认导入时按最新客户状态重新检查；导出支持未归档、已归档或全部客户及自选字段。保留旧的默认导出命令。
- **审计。** 在 Core 侧按来源、对象、日期与关键词筛选，再对匹配记录分页。可从审计结果打开仍可定位的客户、候选客户、跟进、来信或草稿。
- **共享组件与接口。** 使用现有 FTW 面板、状态标签、确认弹窗、分页、Lucide 与 TanStack Query。新增桌面数据命令 `data_overview`、`inspect_backup`、`audit_workspace`、`export_selected_contacts`，导入报告增加表头映射。SQLite Schema 维持 16。[开源组件来源](../THIRD_PARTY.md)

## 桌面复验与核心回归

- 首轮对照后修正总览统计卡的列宽和审计详情的可见性。三张卡铺满工作区，完整审计表可独立滚动。在 1600 × 900 和 1280 × 720 复验总览及审计。
- 桌面创建两份 SQLite 快照，校验真实样本文件的哈希。先取消恢复，确认当前数据未变，再执行恢复。验证导入后新增的测试客户已回到目标快照状态，关联客户文件完整，恢复审计和恢复前安全快照均存在。Core 测试覆盖无效 SQLite 备份拒绝。
- 用实际 WebView 文件输入读取 CSV，预览时 1 条可导入、1 条重复，预览期间客户数据无变化。确认导入后核对持久化和可选字段导出的行内容。审计测试翻到第二页，按来源和邮件主题筛选，并打开实际草稿。
- `npm run lint`、`npm run build`、Tauri 构建、29 项 Rust 测试、2 项前端数据刷新测试和两个 MCP stdio 协议版本均通过。Vite 仍提示约 738 kB 的主包大小。真实邮箱、Win11 及 Windows 125%／150% 系统缩放留待整体验收。

打开 `.ftw-dev/ui-phase4-data-preview/workbench.exe` 后，进入「数据与审计」。同目录保存 Core、MCP、隔离数据库及配套资料。
