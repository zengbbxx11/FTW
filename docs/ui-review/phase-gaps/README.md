## 已验证的操作

- **Agent 档案增量。** MCP 发来的联系方式和产品兴趣建议出现在已打开的「Agent 数据变更」。采纳后可从 SQLite 读到备用邮箱、型号和估计数量，原首选邮箱和验证标记保留。Rust 回归验证了建议提出后人工写入的采购数量仍受到保护。来源类型、网址和说明随建议保留。
- **逐条尽调证据。** MCP 创建候选及证据后，桌面可以通过证据网址找到候选。已验证采信 Agent 证据和手工添加证据，调查时间、核验结果和记录来源各自保存。逐条证据审核与候选转正独立。
- **高级筛选。** 8 位匹配客户均计入总数，预览显示前 5 位。切换邮箱列立即更新预览，组合条件匹配的数量与应用后的客户表格一致。预览列设置只作用于预览。
- **样品跟踪。** 同一客户的两个样品批次状态各自可见。切换到具体批次后能看最近沟通、保留上一条已记录的型号与数量，并沿用批次编号追加桌面跟进。旧记录仍可见，未填写编号的活动标为未分批。
- **质量检查。** 同一隔离库检测到网站资料异常、样品阶段与进度矛盾，以及不开发客户仍有关联发信任务。已验证“核对样品进度”进入现有客户编辑器的业务状态分区。历史人工联系时间颠倒规则已接入，桌面复验样本未覆盖该异常。
- **视觉复验。** 第一轮截图发现证据状态重复显示，Agent 来源位置偏下。复验版将核验状态合并为可操作控件，把来源移到历史值之前，并为批次行提供可区分的无障碍名称。

## 构建与兼容

`npm run lint`、`npm run build`、31 项 Rust 工作区测试、2 项刷新测试、Tauri 构建和两版 MCP stdio 回归通过。实际启动旧库副本验证 Schema 19 迁移，历史候选来源及待审变更保留。此次复用 Radix Popover、现有审查确认、TanStack Query、React Query Builder 和 Lucide，没有增加前端依赖。Vite 仍提示主包约 761 kB。[MCP 工具与参数](../../MCP_MAIL.md) · [开源组件来源](../THIRD_PARTY.md)

本轮为分阶段验证，真实邮箱联调、Win11、Windows 125%／150% 系统缩放及正式便携版发布继续暂停。

项目内的 `.ftw-dev/ui-completion-preview/workbench.exe` 已验证可以启动隔离 Core。同目录的 Core、MCP 与样本数据供预览使用。
