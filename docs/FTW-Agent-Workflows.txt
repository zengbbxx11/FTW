FTW · 可直接粘贴给 Codex 或 WorkBuddy 的任务模板

每次选择一段。把方括号中的内容换成实际目标。先按 FTW-Agent-Quickstart.txt 完成 MCP 接入。

【1｜验证接入 / 查客户】
请只用 FTW MCP 的 list_customers 搜索「[客户名称；样本版可填验收样本]」。列出返回的姓名、公司、阶段、客户等级和主要邮箱。若明确指定了某位客户，再用 get_customer 和 get_customer_timeline 给我最新联系记录。本次只查询。工具不可用时报告实际错误。

【2｜录入候选与跟进】
请处理这份调查资料：[粘贴公司、联系人、邮箱、网址、来源和已核实信息]。通过 list_customers 查姓名、公司和邮箱，有邮箱时用 check_customer_outreach 查看精确邮箱、同域客户和历史。如果已有唯一对应的客户，先读 get_customer；已核实的新事实才可更新，带最新修订和数据纪元；推断用 update_customer 的 review_only=true 提交待核对。若无对应客户，把调查当作候选，用 create_lead_candidate 保存来源和待核实点。若匹配歧义或返回重复，列给我核对。每次写入使用稳定的 request_id。若我提供的是一次已发生的沟通，再用 add_customer_activity 记录实际发生时间和内容。返回客户或候选 ID、做了什么以及待确认项。这次不发邮件。

【3｜起草并转人工审核】
请用 FTW 给「[客户名或邮箱]」准备一封[语言]的[邮件用途]邮件。重点写[产品、需求或本次跟进内容]，发件邮箱指定为[发件邮箱]。先查询客户、沟通历史和真实收发件地址。首次开发先用 check_customer_outreach 查重；发现阻拦或归属不明确时暂停。用 create_email_draft 创建纯文本草稿，再用 request_email_approval 提交人工审核。返回草稿 ID、主题、收发件邮箱和当前状态，到此停止，等我在 FTW 批准。

批准后，可在 FTW 直接点「发送已批准版本」，也可另发这一句：
  请查看 FTW 草稿 [草稿 ID] 的当前修订。若该修订已人工批准且未过期，用 send_approved_email 提交一次，并用 get_email_draft 核对状态。若已入队或已有结果，只返回状态。若结果未知，停止重发。请区分已排队、SMTP 已接受、失败和结果未知。

【4｜在已授权范围内发送当前草稿】
我已在 FTW 为这个客户端开启持续授权。请处理这份已核对的草稿 [草稿 ID]，发送用途为 [首次开发 / 开发跟进 / 样品沟通 / 其他业务]。只发送这一封。先用 get_email_draft 核对收件人、发件账户、当前修订和既有作业。首次开发用 check_customer_outreach 检查重复、拒发和同域线索；遇到阻拦或归属不明时暂停。使用正确的 purpose、当前 revision、稳定的 task_id 和 request_id 调用 send_authorized_email。权限不足或有既有作业时返回真实原因，不改换发件账户或用途。提交后用 get_email_draft 核对实际状态，返回草稿 ID、作业 ID 和结果。结果未知时不重发。

【5｜查回复并交接下一步】
请核查「[客户名或邮箱]」在「[发件账号]」上的最新回复。查询客户和账号，若我授权同步则调用 sync_mailbox，再用 list_inbox 和 get_email_thread 查已关联会话。告诉我同步是否完整、最近一封相关来信日期、客户明确说了什么、还有哪些待确认问题。若邮件归属不明，列出待核对项。若我要求回写，只记确认过的独立沟通事实，不重复生成已有邮件事件。先给我建议的下一步，本次不发邮件。
