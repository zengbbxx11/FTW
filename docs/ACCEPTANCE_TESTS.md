# FTW Windows 便携版与协同验收用例

用于当前源码构建的 Windows x64 ZIP。完整解压后双击 `acceptance\Start-FTW-Acceptance.cmd`，在「系统状态」确认 Core 版本为 `1.1.7`、数据库版本为 `27`、数据目录指向 `acceptance\workspace\data`。验收目录会保留数据和已复制的程序。复验另一份构建或需要空库时，使用全新的解压目录。根目录 `workbench.exe` 使用日常数据目录 `data`。

本版为 1.1.7、Schema 27。已完成编译、静态检查和本机升级后的数据保留核对；下列完整用例尚未在本版全量重跑。历史测试结果不等同于本版通过。[当前验证范围](https://github.com/zengbbxx11/FTW/blob/main/docs/PROJECT_STATUS.md)

先复验空状态和客户表单，再导入随包附带的虚构客户。纯界面和 CRM 用例可跳过邮箱配置。需要实际收发时，使用隔离数据库和获准的测试邮箱或本地模拟服务器。每项记录通过、失败或未执行。遇到失败，记下用例编号、Windows 版本、窗口尺寸、缩放比例及复现步骤，可附上隔离样本截图或诊断 JSON。

| 用例 | 操作 | 预期结果 |

| CRM-02 重开已折叠分区 | 点左侧「业务状态」。点正文标题将其折叠，再点左侧同一项。按同样方式复验「产品兴趣」和「自定义属性」。 | 即使导航已经选中，点击仍能重新展开相应分区。客户类型、样品进度等控件可见。 |
| CRM-03 空属性与草稿保留 | 用刚解压的空工作区，在新增表单填入姓名 `导航验收客户`，不保存客户。点「自定义属性 → 管理自定义字段 → 新增字段」，保存一个名为 `验收属性` 的文本字段，再点「返回新增客户」。 | 创建前显示「尚未配置自定义字段」。返回后仍在自定义属性区，出现 `验收属性` 输入框。切回基本信息，原先输入的姓名还在。 |
| CRM-04 自定义值与持久化 | 接续 CRM-03，填入 `样本值` 并保存客户。退出并重新打开工作台，搜索 `导航验收客户`，打开详情。 | 能找到该客户。详情里的自定义属性显示 `验收属性` 和 `样本值`。 |
| CRM-05 窄窗编辑 | 将窗口调到约 1000 × 740 像素。用 CRM-04 客户行末的铅笔进入编辑，点「业务状态」，再点「备注与需求」。 | 弹窗底部在窗口范围内。滚动发生在弹窗内部，业务状态和备注字段都可到达，保存按钮保持可见。 |
| CRM-06 编辑返回 | 在 CRM-05 中改一项后点「取消」。先选「继续编辑」确认值仍在，再取消并选择「放弃修改」。 | 返回原客户详情。详情保留保存前的值。 |

## 客户开发与跨设备排障

做双向协同用例时，将本地 MCP 客户端临时指向本次解压目录下的 `acceptance\workspace\ftw-mcp.exe`。本机连接无需登记；需要发信时为“本机 Agent”设置授权。使用验收数据和隔离测试收发地址。

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| AGENT-03 双向建档和跟进 | 桌面新建样本客户，用 MCP 查询。再用 MCP 提交候选和完整正式客户档案，来源证据按需填写，为正式客户添加样品跟进。保持桌面客户列表或详情打开。 | 两端读到同一客户资料。新增记录或跟进自动出现在工作台，审计记录正确的操作主体。 |
| AGENT-04 共享视图和冲突 | 在桌面保存视图，通过 MCP 执行。再用 MCP 更新共享视图和客户字段。使用旧修订重新写入，并在工作台暂停本机 Agent 后再调用。 | 视图按同一条件查询，桌面获取最新数据。旧修订触发冲突或待核对结果，暂停后调用被拒绝。 |
| AGENT-05 本机接入 | 在同一 Windows 用户下用两个 MCP 客户端连接，第一个创建资料，第二个查找并更新。在工作台暂停、恢复本机 Agent。 | 两个客户端无需令牌即可使用共享业务，审计记录共享的“本机 Agent”身份。暂停后返回 `mail_agent_paused`，恢复后可继续使用。 |
| MCP-01 精简结果 | 查询客户列表，再读客户详情。查询工作台摘要，将定义版本传回 `get_workbench_definitions`。提交包含成功项和失败项的跟进批量请求。 | 列表有摘要、记录版本和后续分页位置。相同定义版本只返回命中状态。批量响应保留成功项并逐项报告错误。 |
| MAIL-03 首次开发与回执 | 用测试地址执行开发查重、建草稿和持续授权发送，读回草稿或发送作业。完成后对同一目标尝试第二次首次开发。逐封模式另测一次批准流程。 | 入队、SMTP 接受与异常有独立状态。首次开发重复被拦截。持续授权只在所保存的范围内生效，逐封模式校验当前修订。 |
| MAIL-04 收件与会话回复 | 同步测试邮箱，用 `get_mailbox_sync_status` 检查时间与结果。在桌面或用 `create_reply_draft` 回复已确认关联的业务来信。 | 双方都能看到原会话和回复草稿。发送后保留回复邮件头，收发记录归入原会话。同步范围不足时保留相应提示。 |
| FILE-01 附件互通 | 在桌面与 MCP 分别上传样本文件并从另一侧下载。用隔离发件账户附加样本 PDF 并发送。 | 客户文件关联和字节一致。桌面可另存 PDF，发送记录保留附件，发件结果以队列为准。 |
| DIAG-01 本地诊断 | 在「系统状态」导出 JSON。关闭工作台后，在一次性解压目录里双击 `FTW-Diagnostics.cmd`，另用缺少 Core 的副本复验。 | UI 和脚本均生成本地报告，包含版本与运行环境。缺少 Core 时输出最小报告。报告中没有账号凭据、令牌、客户和邮件正文。 |
| MIG-01 升级与换设备 | 用旧版的隔离数据副本重复升级流程。换设备时用停用后的便携隔离目录，重新填写测试 SMTP、IMAP 凭据并指向新 MCP 路径。 | 迁移前有备份，已有客户、已发、审批、文件和会话可读，Core 显示 Schema `27`。两端连接同一新工作区，测试邮箱重新验证后可用。 |

## 已记录的验证

以下为前期开发的历史记录。1.1.7 本轮未重跑这些完整测试；本轮证据以[项目状态](PROJECT_STATUS.md)为准。

Schema `27` 通过 38 项 Rust 测试、前端 lint 和生产构建、2 项刷新测试及两个版本的本地 MCP stdio 回归。旧库升级测试验证迁移前备份、原登记令牌与发信授权记录、暂停和恢复。回环邮件测试覆盖 SMTP、IMAP、拒发、幂等、未知结果和会话回复。

正式 ZIP、在另一台设备部署、真实 SMTP／IMAP、Win11 和 Windows 125%／150% 缩放的发布验收仍待执行。上方用例用于记录这些环境的实测结果。
